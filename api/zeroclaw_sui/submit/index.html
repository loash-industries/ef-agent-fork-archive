Module submit 

Expand description

Verify, reserve, sign, submit — in that order.

The ordering is a safety property, not a style choice. Local verification runs before the transaction is shown to anyone, so a payload that was never going to be signed is not sent off-box. Signing runs after the reservation, because the signature commits to the gas payment and a transaction cannot be re-gassed once signed.

The signer-api decides the gas budget itself, which means the amount is not ours to choose — only to refuse. max_gas_budget is that refusal: a budget larger than the operator sanctioned stops the submission before signing.
