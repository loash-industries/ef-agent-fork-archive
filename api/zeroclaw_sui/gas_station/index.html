Module gas_station 

Expand description

Client for the Trinary Exchange signer-api sponsorship endpoints.

The flow is inverted from a plain gas station: the service wants to see the transaction before it will fund it. reserve takes the unsigned body, validates its Move calls against a server-side allowlist, decides the gas budget itself, and returns coins owned by the sponsor. The caller then rebuilds the transaction with that gas, signs it, and calls execute.

Two wire details drive the error handling. Failures arrive as flat {message, error, statusCode} bodies on non-2xx, and — more dangerously — execute answers 200 even when the transaction did not land: a submission failure appears in error, and a transaction that executed but aborted in Move reports it in effects.status. Reading only the status code would call both of those a success.
